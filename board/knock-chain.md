## 아쉬운 점 (숨기지 않음)
- 양·목자는 구체·원뿔 조립이라 "캐릭터"로서는 단순하다. 밤이라 실루엣+등불로 읽히긴 한다. 3단계에서 모델(또는 2D 스프라이트)로 올릴지 결정 필요.
- 빗나갔을 때의 "장면 변화"는 힌트 문구 + 밤 어두워짐뿐. 기획서의 "양이 다른 곳으로 옮겨 가 울음소리로 위치를 알려 준다"는 아직 없음(양 울음 음원도 없음).
- Night 2·3의 성공 창(4.5%·6.2%)이 좁다. 궤적 점선이 있어 조준은 되지만, 사용자가 "운"으로 느끼면 각도 창을 넓히는 쪽으로 레벨을 고친다(풀이기로 % 를 보며).
- iOS 인앱 브라우저 시트 제스처와의 충돌은 이 환경에서 못 본다 — 사용자 폰에서 "당기다가 창이 닫히는지" 확인 필요.
- 헤드리스(SwiftShader)라 실제 폰 fps 는 못 쟀다. 그림자 맵 2048 + 점광 6개 — 구형 폰이면 느릴 수 있음(그럴 땐 점광 줄이고 그림자 1024).

## 다른 세션에 알리는 노하우
- **물리 레벨은 코드로 증명한다**: 물리를 렌더와 분리(`physics.js` 는 three 없이 node 에서 돎) → 풀이기로 전수 탐색 → 성공 % 와 해 1개를 레벨에 기록 → 로봇이 그 해를 **진짜 터치 드래그(CDP Input.dispatchTouchEvent)** 로 재현. "클리어 가능"과 "너무 좁은 창"을 숫자로 본다. 시소 레벨은 해 0 → 도미노로 교체했듯이, 디자인 감이 아니라 풀이기로 결정.
- Planck.js 결정론: 고정 타임스텝 + 콜백 안에서 destroyBody 금지(큐에 넣고 step 뒤 처리) + 난수 없음 → 로봇의 지문(hash) 비교가 매번 같다.
- 도미노가 안 넘어지고 미끄러지면: 키를 키우고(1.4), 밀어야 할 물체를 가장자리에 **걸치게**(무게중심 0.1 안쪽) 둔다. 무거운 돌은 도미노로 못 민다.
- 어두운 씬은 반구광 1.1 + 방향광 1.4 가 하한. 그 밑이면 폰에서 검게 보인다. 따뜻한 점광(거리 감쇠 decay 1.6)으로 "등불" 느낌.
- three.js 로 HUD 겹칠 땐 캔버스 `prepend`. 프로젝트 `package.json` 이 `"type":"module"` 이면 Playwright 로봇은 `.cjs`.
- esbuild 를 node_modules 복사로 가져오면 `.bin` 링크가 없다 → `node_modules/esbuild/bin/esbuild` 를 직접 실행(바이너리, `node` 로 돌리면 안 됨).
