# How It Works — 레슨 작성 가이드 (세션·작업자 공통)

레슨 1개 = 파일 1개 `howitworks_app/lessons/NN-key.js` (NN = 며칠째 레슨, 01~30). 기준 예시: `01-microwave.js`, `02-toilet.js`, `06-zipper.js` — **새 레슨을 쓰기 전에 셋 다 끝까지 읽는다.**
빌드: `python3 tools/howitworks/build.py` (모든 레슨 → `docs/how-it-works.html`).
일부만 미리보기: `python3 tools/howitworks/build.py --only lock,pen --out <scratch>/p.html`
검사 로봇: `node howitworks_app/qa/robot.js <scratch폴더> --html <scratch>/p.html --only lock,pen` → `<scratch폴더>/lessons/<key>.png`(정지), `<key>-play.png`(재생 중) 스크린샷을 **반드시 직접 열어 본다.**

## 파일 모양
```js
{
/* 5. Pin tumbler lock */
const SOMETHING = '...';            // 필요하면 상수 (블록 안이라 다른 레슨과 안 겹침)
LESSONS.push({
  key: 'lock', title: 'Pin Tumbler Lock', cat: 'Home', mins: 3, vb: [360, 260],
  summary: '…',                      // 한두 문장, 240자 이내. 핵심 원리를 한 번에.
  parts: [ { n: 1, name: '…', at: [x, y], num: [x, y], desc: '…' }, … 6개 ],
  steps: [ { text: '…', parts: [1, 2], t: [0, 1.8] }, … 3~4개, 0 부터 dur 까지 빈틈없이 ],
  dur: 8,                             // 5~10초
  why: 'Why …? …',                    // "왜 이렇게 만들었나" 설계 이유 1~2문장 (60~300자)
  fact: '…',                          // 놀라운 사실 1개 (300자 이내, 숫자는 출처에서 확인된 것만)
  quiz: { q: '…', opts: ['…', '…', '…'], a: 1, why: '…' },   // 정답 위치는 레슨마다 섞는다
  sources: [ ['제목 — 사이트', 'https://…'], … 3~4개 ],      // 위키 말고 하나 이상(정부·대학·제조사·교과서급)
  art(p) { return `…SVG 조각…`; },
  anim(svg, p, t) { … }               // t == null 이면 정지 그림(설명용 기본 상태). 숫자 t(초)면 그 순간.
});
}
```
- cat 은 `Kitchen` · `Bathroom` · `Home` · `Getting Around` · `Digital` 중 하나.
- UI·문구 전부 **미국 영어**(인치·화씨·갤런 먼저, 필요하면 괄호로 미터법). 이모지·한글 금지. 다른 앱 이름(SmartyMe 등) 금지.

## 그림 규칙 (사용자 승인된 '공책 스케치' 결 — 바꾸지 않는다)
- 캔버스: 가로 360, 세로 240~280 (`vb`). 배경 모눈은 엔진이 깔아 준다. 엔진이 그림 전체에 손떨림 필터를 건다.
- **단면도(cutaway)**: 잘린 벽은 `fill="url(#${p}hatch)"` 45° 해칭, 속은 보이게. 빈 공간(구멍·관 속)은 `fill="url(#${p}grid)"`.
- 클래스: `ink`(기본 선 1.5) · `thin`(가는 선) · `fm`(금속 연회색 채움) · `fw`(흰 채움) · `water`(물 연파랑) · `wline`(수면 선) ·
  `energy`(빨강 파동·에너지·전기) · `flow`(파랑 흐름 화살표) · `hand`(손글씨 작은 라벨, 짧게·드물게). 천은 `url(#${p}fabric)`.
- **색은 3개만**: 먹색 선, 빨강(번호·에너지·움직임), 파랑(물·공기·흐름). 그 밖의 색 금지(회색 톤 채움은 OK).
- 부품 강조 때 흐려지는 건 `.art` 바로 아래 요소 중 **opacity 속성이 없는 것**만이다(10-16 수정). 애니메이션으로 opacity 를 바꾸는 겹침 그룹은 그대로 보이고, opacity="0" 은 계속 숨는다.
- `stroke="…"`·`stroke-width="…"` 속성도 마찬가지로 존중된다(10-16 엔진 수정).
- `fill="…"` 속성을 쓴 요소에는 CSS 가 fill 을 덮지 않는다(`.ink:not([fill])` 만 fill:none). 색 채움은 속성으로 주면 된다.
- 모든 id 는 `${p}` 접두(`id="${p}piston"`) — 같은 페이지에 썸네일로 또 그려지기 때문.
- **부품 6개는 각각 `<g data-part="n">` 로 묶는다.** 번호를 탭하면 그 그룹만 빨갛게, 나머지는 흐려진다. 부품이 아닌 배경(외곽·바닥)은 `<g class="shell">`.
  빈 그룹 금지(로봇이 잡는다). 지시선 끝점 `at` 은 그 부품 그룹 상자 ±14 안. 번호 원 `num` 끼리 22 이상, 캔버스 가장자리 10 안쪽.
- 번호 원은 그림 바깥 여백이나 빈 곳에 두고 지시선이 짧게 가게. 원이 다른 선을 가리지 않게.
- 그림은 '이해되는 단순화': 진짜 구조와 맞는 비율·배치, 하지만 선은 최소. 클립아트·귀여운 얼굴·장식 금지. 공대 노트 단면도처럼.

## 움직임 (시그니처 — "와, 이 정도까지?" 포인트)
- See it work 를 누르면 `anim(svg,p,t)` 가 매 프레임 불린다. **원리 그 자체가 움직여야 한다**: 피스톤이 오르내리고 밸브가 열리고, 냉매가 돌고, 핀이 정렬되고, 전자가 흐르고…
  단순 깜빡임·확대·흔들기는 실패. 각 단계(steps)의 t 구간에 그 단계 설명대로 움직임이 일어나게 맞춘다(엔진이 단계 글과 부품 강조를 같이 바꾼다).
- 헬퍼: `wave(points, amp, wavelength, phase)` 사인파 경로(+화살촉), `rot(px,py,cx,cy,deg)`, `seg(t,a,b)`(a~b 동안 0→1 부드럽게), `ease`, `f1`(소수 1자리), `TAU`.
- 움직이는 요소는 `setAttribute` 로 d/transform/x/y/opacity 를 바꾼다. 움직이는 부품을 가리키는 지시선은 `anim` 이 `{ n: [x, y] }` 를 돌려주면 따라간다(지퍼 예시).
- `t == null`(정지) 상태도 원리가 읽히는 그림이어야 한다(예: 전자레인지 정지 그림에도 파동이 그려져 있음).

## 사실 정확성 (가장 중요 — 틀린 원리 = 앱 신뢰 붕괴)
- 모든 숫자·연도·이름은 **WebSearch 로 실제 확인한 출처**에서만. 확인 못 한 건 쓰지 않는다. 흔한 오해(예: "전자레인지는 속부터 익힌다")를 사실처럼 쓰지 않는다.
- 미국 기준으로(전압 120 V, 갤런, 화씨). 제품마다 다른 건 "most", "typically" 로.
- `sources` 에 실제로 근거로 쓴 페이지를 넣는다. 위키백과 + 하나 이상은 정부(.gov)·대학(.edu)·제조사·Explain that Stuff/HowStuffWorks 같은 해설 사이트.

## 품질 점검 (보고 전에 스스로)
1. 정지 스크린샷만 보고도 무슨 물건이고 어디가 어딘지 읽히나? 선이 겹쳐 엉키지 않았나? 손글씨 라벨이 다른 선과 겹치지 않나?
2. 재생 중 스크린샷에서 원리가 움직이는 게 보이나?
3. 로봇 실패 0. 콘솔 에러 0.
