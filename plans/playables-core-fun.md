**관찰**
- Hamster Escape 류(Supersonic 카탈로그: Stacky Dash, Hide N Seek, Bazooka Boy, My Mini Mart)의 공통점 = **손가락을 떼지 않는 연속 조종(드래그/조이스틱) + 2D 공간에서 경로를 고르는 회피 + 레벨 단위 진행(클리어→다음 레벨) + 매 레벨 끝 보상 화면.** 우리 9개 중 이 네 가지를 동시에 가진 게임은 **없다.** 연속 조종은 Climb or Burn·Poop Dodge 둘뿐이고, 레벨 단위 진행은 Catdoku 뿐이다(퍼즐).
- "탭→결과" 느낌의 원인은 조작이 **이산적(탭 1회 = 사건 1회)**이고 **판단 거리가 1초 안쪽**이라서다. 공간을 읽고 경로를 고르는 시간이 없다.
- 하이퍼캐주얼 시장 근거(10-30 조사·Supersonic 목록 플레이 수 1,800만~7,300만): 상위권은 전부 **연속 조종·레벨형**. 반응속도 단독 게임(두더지류)은 목록에 없었다. (표본 = 사용자 캡처의 Supersonic 페이지 1장 — 전체 카탈로그 통계가 아님.)

## 3. Chicken Cross 개선 방향 (제안 — 사용자 OK 뒤 개발 세션)
핵심은 그대로(탭 전진, 콤바인 추격, 기차 경고등, 조크). 얹는 것은 **공간 판단과 진행 단위** 두 가지뿐.
1. **가로 이동**: 좌/우 스와이프(또는 화면 좌우 1/3 영역 탭)로 한 칸 옆으로 — "이 차선은 막혔으니 옆으로 돌아가자"가 생긴다. 탭 전용 원칙은 유지(스와이프는 탭의 확장, 홀드 없음).
2. **차선 다양화**: 통나무 떠내려오는 강(타고 이동), 멈춘 차(장애물), 신호등 횡단보도(안전 구간) — 각 차선이 다른 판단을 요구.
3. **구간(zone) 진행**: 50칸마다 구간 전환(농장→마을→고속도로→밤), 구간 끝에 "GOOD JOB!"식 짧은 결산 화면 → 여기가 상자 진행 바·보상 제안(망치 수집과 같은 A 방식)의 자리. 날짜 시드·랭킹은 유지.
4. **캐릭터 스킨 1종류**(닭 품종/모자 — 원작 디자인): 수집 보상. 플레이 중 항상 보이는 주인공이라 꾸미기 효과가 망치보다 크다.
5. **연결 애니메이션**: 전진 점프 호(arc)·착지 스쿼시·깃털, 구간 전환 카메라 이동 — "이어지는 움직임" 느낌.
먼저 웹 미리보기(`docs/chicken-cross.html` 은 그대로 두고 복사본)에서 1·2·5만 넣어 사용자 느낌 → OK 면 3·4 → Playgama 판.

## 5. 제작 제약 재정비 (2026-11-01, Codex 조사 반영)

- **"파일 1개·100KB·탭 전용·엔진 없음"은 우리 카탈로그의 현재 제작 습관이지 YouTube 요구사항이 아니다.** 앞으로의 기획 절대 조건으로 삼지 않는다.
- YouTube Playables 공식 요건(MUST 본문 기준, Codex 확인 — 이 환경은 developers.google.com 차단): Canvas/WebGL 허용, 초기 번들 **MUST < 30 MiB**(SHOULD < 15 MiB), 전체 < 250 MiB, 터치·마우스 필수·방향키 권장, 반응형, 빠른 로드. Playgama 는 zip 300 MB·index.html 루트·Bridge SDK.
- 뜻: 크기를 불필요하게 늘리라는 게 아니라, **성능 예산 안에서 필요한 아트·애니메이션·레벨 데이터를 허용**한다. 탭 전용도 모바일 웹 안전 원칙(홀드·시트 제스처 충돌 회피)에서 나온 것이지 드래그 금지가 아니다 — Playgama/YouTube 는 전체 화면 iframe 이라 iOS 인앱 시트 문제가 없다(단 Pages 미리보기는 여전히 시트에서 열린다 → 미리보기엔 완충지대 유지).
- 시장 표본(독립 트래커 playables.games/best, 10-31 누적 공개 플레이): Tall Man Run 111M · Build a Queen 106M · Snake Clash 103M · Going Balls 100M · Stealth Master 98M · Dessert DIY 94M · Thief Puzzle 94M · My Mini Mart 61M. **누적 플레이일 뿐** 수익·잔존·상승 속도·인과가 아니고 기존 IP·노출·기간 편향이 있다. 동작 유형은 연속 조작 회피·수집(Tall Man Run, Snake Clash, Going Balls), 짧은 잠입/공간 퍼즐(Stealth Master, Thief Puzzle, Hamster Escape), 손맛 변형/DIY(Dessert DIY, Build a Queen), 생각하는 탭 퍼즐까지 다양 → **드래그/3D 만 정답 아님.**
- 1차 퍼블리셔 사례(Supersonic, Tall Man Run, 2022 모바일): 재미있는 변형 메커닉 → 장애물/레벨 변화 → 만족스러운 엔딩 → 스킨·테스트 순. YouTube 수익 효과로 일반화 금지.
- **현재 작품 문제의 재진단**: 탭 동작 자체가 아니라 **의사결정·상태 변화·연결된 피드백·레벨 변주·다음 목표의 밀도**가 약한 것. 코드 확인: 원본 Mole Mash 는 타이틀→45초 타이머·하트 3개·3×3 보드(`docs/mole-mash.html` lives=3), Chicken Cross 는 점프 easeOut 0.11초·연타 버퍼·죽음 깃털, Climb or Burn 은 pointermove 조종·물방울/상승기류·마일스톤이 **이미 있다.** 애니메이션이 전무한 게 아니라, 한 판이 "버튼→점수→재시작"으로 닫히고 **한 세계 안에서 이어지는 상태 변화(이동→읽기→기다림/우회→통과→탈출)**가 없다. 장식 애니메이션·스킨만으로 해결했다고 하지 않는다.
- 범위 분리: **Mole Mash 샌드박스 + v1.1 실험(A)** 은 파이프라인·보상 루프 검증 트랙. 아래 신규 기획은 **별도 트랙**(대표 1개 코어 플레이 시제품으로 검증, 양산 금지).

- **1순위 (2) 조준 + 물리 연쇄.** 이유 ① 사용자가 반복해서 원한 "한눈에 읽히는 목적"이 **인과 사슬로 화면에 보인다**(Bow or Die 에서 가져올 명료함) ② 한 레벨이 10~30초로 짧고 실패가 즉시 이해됨 ③ 아트 기준(입체 블록·일관된 그림자·충돌 피드백)을 **한 화면에서 보여 주기 가장 쉽다** — Cargo Sort 류 "진짜 게임 같은" 인상과 같은 재료 ④ 수작업 레벨 3개로 코어 테스트 가능. 위험은 물리 예측 가능성 — 궤적 점선과 결정론적 물리(고정 타임스텝)로 운 요소를 제거해야 한다.
