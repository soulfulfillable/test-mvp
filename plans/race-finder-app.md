# 5K·마라톤 찾기 (가칭 Race Finder) — 기획서 (기획 파트너, 2026-11-14)

## 왜
- 사용자 아이디어: "포켓몬 대회를 모아 보여 주는 앱을 사람들이 계속 쓴다더라 — 그런 것 중 차별화되는 것". 구조 = **흩어진 대회 정보를 한곳에 + 대회가 계속 열려 재방문**.
- 수요: RunSignup 한 곳이 2025년 대회 9.7만 개·등록 1,220만 건(미국 지구력 대회의 50% 이상 추정), 참가 3년 연속 성장(+11%·+8%·+5%).
- 경쟁: ACTIVE(집계 사이트 기준 3.5점)·Runelo·Let's Race!·Run Calendar·RaceGuide — 뚜렷한 1등 없음. **평가 수·리뷰 원문은 미확인**(기획 세션에서 App Store 접속 불가) → 개발 세션 ①에서 확인.
- 불만(포럼): "대회를 찾으려고 사이트 열두 개를 돈다", "동네 단위로 못 좁힌다", "접수 링크·시간 정보가 없다", 검색이 투박하다.
- 광고 수익 연결: 대회 시즌 내내 주 1~2회 여는 앱 → 목록 하단 배너. 접수는 외부 페이지로 보내므로 결제·고객지원 없음.

## 핵심 화면 (하나를 끝까지)
- **"This weekend near me"**: 열자마자 위치 기준 가까운 대회가 날짜순으로. 검색·로그인·온보딩 없이 첫 화면이 곧 답.
  - 한 줄에: 요일·날짜, 대회 이름, 거리 종목(5K/10K/Half/Full), 동네·몇 마일 떨어졌는지, 접수 마감까지 남은 날.
  - 거리 종목·반경(10/25/50 mi)·기간(이번 주말/이번 달/3개월) 필터 — 칩 3줄, 설정 화면 없음.
  - 누르면 상세: 지도 한 장, 출발 시각, 종목별 참가비, **공식 접수 페이지로 가는 버튼 하나**.
- 위치 권한을 안 주면 ZIP 코드 입력으로 똑같이 동작.
- 저장(하트) → 접수 마감 전·대회 전날 로컬 알림.

## ✨ 와 포인트 (보고 때 이 장면을 스크린샷·영상으로)
- **"참가비가 금요일에 오릅니다"**: 대회마다 참가비가 오르는 날짜를 계산해 목록에 "Price goes up in 2 days ($30 → $35)" 로 보여 주고, 저장한 대회는 오르기 전날 알림. 기존 찾기 앱은 날짜·장소만 보여 준다.
  - ⚠️ RunSignup 대회 데이터에 접수 기간별 참가비가 들어 있다고 기억하나 **미확인** — 개발 세션 ①에서 실제 응답으로 확인. 없으면 대체 와 포인트: "이번 주말 타임라인"(토·일을 시간축으로 펴서 출발 시각·이동 거리까지 한눈에).
- 생각지도 못한 배려: 대회 날 아침 그 장소의 예상 기온(Open-Meteo 등 무료 예보)을 한 줄로.

## 원칙
- 전부 무료, 배너만(목록 하단 1곳). 계정·서버 없음. 접수·결제는 하지 않고 공식 페이지로 보낸다.
- 화면 숫자는 진짜만 — 참가비·마감일을 못 받아 오면 칸을 숨긴다(추정값 금지).
- 출처 표기("Race data from RunSignup")와 "not affiliated" 문구를 About 에.
- 미국 App Store, 영어 UI, 마일 기준, 아이폰 전용·세로. `DESIGN.md` 적용(새 앱).
- 빈 화면("근처에 이번 주말 대회가 없어요 → 반경 넓히기 버튼")·오프라인(마지막으로 받은 목록+받은 시각)·첫 실행·큰 글씨·다크 모드까지.

## 데이터 — 사용자 결정(11-14): 문의 메일 없이 바로 만든다
- RunSignup `GET /Rest/races`(공개 대회 목록, 인증 없이 공개 대회 반환, 페이지당 최대 1,000). ZIP+반경·날짜·종목 파라미터가 있는지 ①에서 확인.
- **위험(중간)**: API 개발자 계약(2026-09-03)에 "RunSignup 과 경쟁하는 앱 금지"·"등록 후 사용" 조항. 우리는 접수 페이지로 보내기만 하므로 막힐 가능성은 낮다고 보지만 확인된 것 아님. → 데이터 층을 **출처 교체 가능한 인터페이스**로 만들어 끊겨도 다른 출처로 바꿀 수 있게.
- **API 키·시크릿을 앱에 넣지 않는다**(계약상 제3자 제공 금지 + 유출). 인증 없는 공개 호출만 쓰거나, 안 되면 GitHub Actions 가 하루 한 번 받아 정적 JSON 으로 올리는 방식을 사용자에게 A/B 로 묻는다.
- 한계: RunSignup 에 없는 대회(Active 등 나머지 절반)는 안 나온다 → "대회가 빠졌다" 불만 가능. 1차는 RunSignup 만, 반응 보고 넓힌다.
- ⚠️ 기획 세션 환경에서 `runsignup.com` 접속이 막혀 있었다(프록시 403) → 개발 세션은 환경 네트워크 허용 목록에 `runsignup.com` 추가가 필요할 수 있다.

## 진행 기록 (개발 세션이 추가, 최신이 위)

### 2026-11-14 웹 시제품 1차 (기획 세션에서 이어서 개발 — 사용자 "여기서 그냥 개발해줘")
- **API 확인(①)**: `GET https://runsignup.com/Rest/races?format=json&events=T` 는 인증 없이 200. 종목마다 `registration_periods[{registration_opens, registration_closes, race_fee}]` 가 있어 **참가비 인상 일정이 실제로 들어 있다 → 와 포인트 가능**. `zipcode`+`radius`, `state`, `start_date`/`end_date` 필터 동작.
- **제약 3가지**: ①응답에 CORS 헤더가 없고 JSONP 도 안 됨 → **브라우저(웹)에서는 직접 못 부른다**(네이티브 앱은 상관없음) ②인증 없는 호출은 **한 질의에 1,000개까지**(2페이지부터 "requires authentication") ③가상(virtual) 대회·1년짜리 챌린지·모임 달리기가 많이 섞여 있어 걸러야 한다(`event_type=virtual_race`, 종목 시작일이 기간 밖).
- **그래서 시제품 데이터는 오늘 받은 스냅숏**: `racefinder_app/tools/fetch_races.py` 가 주(state)별로 8주치를 받아(1,000개 차면 기간을 반으로) 걸러서 위·경도 2° 조각 파일로 저장 → `docs/race-finder-data/`(대회 5,101개, 조각 209개 + ZIP 좌표 10개, 5MB). 화면에 "last updated Nov 14" 표기. ZIP 좌표는 npm `zipcodes`(BSD).
- **화면** `docs/race-finder.html`: 첫 실행(내 위치/ZIP) → 날짜별 목록(출발 시각·이름·종목·동네·거리) → 기간 3개·거리 5개 필터 → 상세 시트(종목별 지금 참가비, **가격 계단 그림**: 지나온 구간은 초록, 오늘 위치 점, 다음 인상가는 주황) → RunSignup 접수 페이지·저장·달력 파일(.ics). Saved 탭. 빈 화면(넓히기 버튼 3종)·오프라인(다시 시도)·위치 거부(ZIP 안내)·다크·큰 글씨.
- **테스트 로봇** `racefinder_app/test/robot.js`: 68개 통과/0 실패. 첫 실행·내 위치, 필터 15조합(결과가 종목과 일치하는지 포함), 반경 버튼, **호보컨 50mi·8주 대회 191개 상세를 전부 열어** 넘침·깨진 글자·접수 링크 검사(가격 계단 110개, 인상 예고 69개), 저장·달력·닫기 3방식, 새로고침 뒤 저장 유지, ZIP 오류 3종, 키보드 높이(390×500), 빈 화면 버튼 3개, 오프라인→재시도, 320×568·375×667·430×932·다크·큰 글씨. 로봇이 잡은 실제 버그 1건: 저장된 위치로 다시 열면 데이터 받기 전에 꼬리말을 그리다 오류.
- **못 한 것·확인 못 한 것**: 실제 아이폰 사파리 미확인(헤드리스 크롬만). 대회 날 기온 한 줄은 안 만듦(예보 주소가 이 환경에서 막힘). 알림은 웹이라 달력 파일로 대신함. 경쟁 앱 평가 수·리뷰는 아직 안 봄. 스냅숏이라 날이 지나면 가격·마감이 낡는다.
- 이 세션용 환경 `test-mvp` 를 새로 만듦(허용: runsignup.com, www.runsignup.com, apps.apple.com, itunes.apple.com).
- 다음: 사용자 느낌 → (계속이면) 이름·번들 A/B → Flutter(기기에서 ZIP+반경으로 직접 호출 — 1,000개 제한·CORS 문제 없음) → 로컬 알림(인상 전날).
